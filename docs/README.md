# Docs

| Folder | What goes in it |
|---|---|
| `design/` | How things work now. Current state only: no history, no dates, no plans. Updated in the same commit as the code or data it describes. |
| `proposals/` | Ideas and plans not (fully) built. One file per proposal, named `YYYY-MM-DD-<topic>.md`, with its date and status (proposal, partly implemented, implemented, dropped) at the top. When a proposal is built, its working parts move into `design/` and its status says so. |
| `issues/` | Open problems. `rules-to-migrate.md`: what the code still decides by a rule instead of from the drawings, what each rule waits for, and the larger steps still to do. `missing-poses.md` (generated): poses the story needs. `missing-props.md` (generated): props the panels use with no drawn art, and the panels' prop wishes. `problem-poses.md`: what looks wrong in the poses and faces, and where to fix it (pose, drawing or code). Fixed problems are removed. |

## Design

- `design/style-bible.md` — the visual rules; the renderer is judged against them.
- `design/pipeline.md` — how drawings and JSON reach the renderer, the labs and the reader site (a Mermaid diagram).
- `design/drawn-parts.md` — bodies from the artist's part drawings: the parts files, how a figure is built.
- `design/faces.md` — faces: the drawing files, and how a head is turned and tilted from its front and side drawings.
- `design/panels.md` — the panel language, reading a panel back as text, the panel lab and publishing.
- `design/panel-writing.md` — the checklist for writing a section's panels: the artist's directions and the lessons from reviews. Read before writing panels; add every new lesson.
- `design/composition.md` — how things are arranged in a panel (sky and horizon, throne, top view). The model panel for each kind of scene: `panels/layouts.md`.
- `design/sequential-grammar.md` — wordless storytelling principles (the clear-line school): camera discipline, cause and effect across the gutter, repetition as time, direction grammar (proposed).
- `design/pose-picking.md` — the pose data (bases and gestures with their finding fields; any pair is a pose), composition (`src/compose.js`), the catalogues and gap report, and the rules for picking a pose.

## Proposals

- `proposals/2026-11-03-scene-spec.md` — scenes as specs or artist templates (spec route implemented as panels).
- `proposals/2026-11-06-held-props.md` — swords and bows along a reference line in the hand (implemented: `data/props/held/{sword,club,bow}.svg` with base + per-character layers, `tools/import-held.mjs`).
- `proposals/2026-11-07-contact-constraints.md` — pin feet while editing in the pose lab (implemented), `lookAt` to aim gazes, `held-by` to put a prop in a hand.
- `proposals/2026-11-07-pose-composition.md` — poses as a base × a gesture (partly implemented, now in `design/pose-picking.md`; open: chest on reclined bases, gaps as products, half-copy in the lab, composition as spec).
- `proposals/2026-11-08-vertical-placement.md` — one `row` for vertical placement, by name or number; `shot` and `zoom` retired (implemented: `design/panels.md`, Rows; open: the row values, `top`'s size).
- `proposals/2026-11-13-any-pair-in-panels.md` — a panel may name any base-gesture pair, composed when drawn (implemented: `design/pose-picking.md`; the reviewed list it kept was dropped 2026-11-14; open: turning upper-body `adjust`s into pairs, a pose picker).
- `proposals/2026-11-20-readable-panels.md` — panels a writer can understand from the JSON: a text read-back of the layout with contact checks, `depth`, surfaces on props, `look` / `holds`, adjust recipes turned into bases, stand-in aliases (partly implemented: the read-back and `depth`, `design/panels.md`).

## Issues

- `issues/rules-to-migrate.md`
- `issues/problem-poses.md`
- `issues/missing-poses.md` — generated by `tools/pose-gaps.mjs`: story moments without a pose, wanted poses (`wanted` in `data/poses.json` is the source: new pose needs found while writing panels go there, each with its stand-in).
- `issues/missing-props.md` — generated by `tools/prop-gaps.mjs`: props the panels use that have no `data/props/<id>.svg`, with the panels that want each, and the panels' prop wishes in their own words. The starting point for a props session.

Related: `data/faces/README.md` (the face drawing workflow), `tools/proto/head-turn/README.md` (the raster head-turn study).
